## 1. Provider catalog: models.dev

- **What it is:** https://models.dev, repo `anomalyco/models.dev` (formerly sst/models.dev). 7.2k stars, MIT, pushed 2026-10-13. Community-maintained TOML files are compiled into a single `https://models.dev/api.json`.
- **Contents (downloaded today):** 5.6 MB raw, about 570 KB gzipped. 228 providers and 8,811 models.
  - **Provider fields:** `id`, `name`, `env` (for example `["ANTHROPIC_API_KEY"]`), `npm` (the AI-SDK package that tells you which wire protocol to use), `api` (the base URL, present for 203 providers), `doc`, `models{}`.
  - **`npm` distribution:** 188 providers use `@ai-sdk/openai-compatible`, 8 use `@ai-sdk/anthropic` and 6 use `@ai-sdk/openai`; the rest are one-offs (google, azure, groq, cohere and others). So almost every provider can be driven by one OpenAI-compatible client with `base_url = provider.api`. A few `api` values contain `${VAR}` templates, for example Cloudflare's `${CLOUDFLARE_ACCOUNT_ID}`.
  - **Model fields:** `id`, `name`, `family`, `attachment`, `reasoning`, `reasoning_options`, `tool_call`, `structured_output`, `temperature`, `knowledge`, `release_date`, `last_updated`, `modalities{input,output}`, `open_weights`, `limit{context,output}`, `cost{input,output,cache_read,cache_write}` (USD per 1M tokens), `canonical_model_id`.
- **How OpenCode uses it** (`anomalyco/opencode` `packages/core/src/models-dev.ts`):
  - It bundles a snapshot (`models-dev/snapshot.txt`, regenerated by `script/update-models-snapshot.ts`) so the first run works offline.
  - The default source is `https://models.opencode.ai`, a mirror of models.dev.
  - It fetches with exponential, jittered retry and caches the body together with a digest, so `refresh()` skips the work when nothing changed.
  - A scoped background task refreshes every 5 minutes (`Schedule.spaced(ttl)`).
  - Each provider's `api` becomes `baseURL` and its `npm` value picks the SDK adapter.
- **Consuming it from Rust:**
  1. Ship a pre-processed snapshot with `include_bytes!` (zstd or gzip, about 0.5 MB). Better still, generate a trimmed postcard or bincode file in `build.rs` that keeps only the fields you need.
  2. Deserialize lazily with `serde_json` into `HashMap<String, Provider>`; use `#[serde(default)]` everywhere and keep unknown fields.
  3. On launch, and then every 24 hours (5 minutes is overkill for a desktop app), send `GET` with `If-None-Match: <etag>`. The server returns `etag` with `cache-control: max-age=0, must-revalidate`. Store the result in `~/Library/Application Support/Synapse/models.json`. User overrides are layered on top.
  4. Map `npm` to an adapter: `@ai-sdk/anthropic` uses Anthropic, `@ai-sdk/google` uses Gemini, `@ai-sdk/openai` uses OpenAI Responses or Chat, and everything else uses OpenAI-compatible with `api`.
  - **rig-core 0.44.0 already does this:** `rig_core::catalog::Catalog::builtin()` is generated from models.dev, and `Catalog::from_models_dev()` / `with_models_dev()` overlay a fetched copy. `Catalog::connect("vendor/model")` builds a client. There is also a third-party `models-dev` crate (0.1.1, 2025, little used), so skip it.
- **Alternatives:**
  - **OpenRouter `GET https://openrouter.ai/api/v1/models`** (461 models today; fields include `context_length`, `pricing`, `supported_parameters`, `architecture` and `reasoning`). Good when the user routes through OpenRouter, but it covers one gateway only.
  - **LiteLLM `model_prices_and_context_window.json`** (BerriAI/litellm, 61k stars; its license field says NOASSERTION, mostly MIT with an enterprise directory). It is rich in prices but has no base URLs or env-var hints.
- **Local providers:** these are not in a static catalog. Probe `http://localhost:11434/api/tags` (Ollama) and `http://localhost:1234/v1/models` (LM Studio, which also has an `lms` CLI), and list them dynamically.

## 3. Reusing installed CLIs: ACP

- **Protocol:** Agent Client Protocol, https://agentclientprotocol.com, `agentclientprotocol/agent-client-protocol` (4.4k stars, Apache-2.0). It is JSON-RPC over stdio. The client (Synapse) spawns the agent subprocess and sends `initialize`, `authenticate`, `session/new` (with cwd and MCP servers), `session/prompt`, and `session/cancel`.
  - The agent streams `session/update` notifications: message chunks, thoughts, tool_call, tool_call_update, plan.
  - The agent calls back into the client with `session/request_permission` (a native ask/allow/deny prompt that maps directly onto Synapse's permission UI), `fs/read_text_file`, `fs/write_text_file` and `terminal/*`.
- **Rust crate:** `agent-client-protocol` 3.3.0 (2026-10-09, Apache-2.0, 5.2M downloads), repo `agentclientprotocol/rust-sdk`. It provides `Client.builder()` and `Agent.builder()` roles, plus `agent-client-protocol-rmcp` for MCP passthrough and `-http` for HTTP/WS transports. Draft protocol v2 sits behind `unstable_*` features; stay on v1.
- **ACP registry:** `https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json` (repo `agentclientprotocol/registry`, Apache-2.0, updated hourly). It is a machine-readable list of about 50 agents with distribution type (`npx` package and args, or per-platform `binary` archive with `cmd`, `args` and sha256). Synapse can consume this list directly to offer "install / use agent X". Registry IDs include claude-acp, codex-acp, gemini, opencode, github-copilot-cli, cursor, goose, cline, junie, kimi, qwen-code, mistral-vibe, factory-droid, kilo, auggie, fast-agent, deepagents, devin, pi-acp, vtcode and others.

- **How Zed does it:** it reads the registry, or user `agent_servers` settings with `command`, `args` and `env`. It installs npx or binary distributions into its own data directory, spawns the process with stdio pipes and runs the ACP client. The agent's MCP servers are passed in `session/new`.
- **Headless fallbacks** (when no ACP adapter is installed):
  - `claude -p "<prompt>" --output-format stream-json --verbose [--input-format stream-json] [--permission-mode ...] [--allowedTools ...]`
  - `codex exec --json [--skip-git-repo-check] [--ephemeral] "<prompt>"` (JSONL events; confirmed in `codex-rs/exec/src/cli.rs`). Codex also has `codex app-server`, a JSON-RPC server.

## 5. Multi-agent orchestration

**State of frameworks**
- **AutoGen** (61k stars) is in **maintenance mode**; Microsoft moved to **Microsoft Agent Framework** (14k stars, MIT).
- **CrewAI** (60k stars, MIT) and **LangGraph** (43k stars, MIT) are Python.
- In Rust, **rig** has `rig-agent` and multi-turn agents but no group chat. **swarms-rs** (The-Swarm-Corporation, 0.3.0, 183 stars) is immature.
- **Recommendation:** don't adopt a framework; write about 1–2k lines of orchestration on tokio using these patterns.

**Patterns worth copying**
- **Anthropic, "How we built our multi-agent research system"** (June 2025, https://www.anthropic.com/engineering/multi-agent-research-system):
  - An orchestrator-worker design: a lead agent plans, saves the plan to memory, and spawns 3–5 subagents in parallel, each with an explicit objective, output format, tool guidance and task boundaries.
  - Subagents run their own search loops with interleaved thinking and return condensed findings. A separate CitationAgent attributes sources.
  - Effort scales with complexity: 1 agent with 3–10 tool calls for simple tasks, 10 or more subagents for complex ones.
  - Results: about 90% better than single-agent on their eval. Token usage explains about 80% of the variance, and multi-agent runs use about 15× the tokens of chat. They stress start-wide-then-narrow search, LLM-as-judge evaluation, and checkpointing for long runs.
- **AutoGen SelectorGroupChat:** a shared thread. A selector LLM, or a custom `selector_func`, picks the next speaker from the agent descriptions and history, with `allow_repeated_speaker` and termination conditions (max messages, text mention such as "TERMINATE", token budget, timeout, handoff). `RoundRobinGroupChat` and `Swarm` (handoff-based) are simpler variants.
- **STORM** (stanford-oval/storm, 31.6k stars, MIT; last push Sept 2025, so stable but quiet): discover perspectives from related topics, then run simulated conversations between perspective-specific writers and a grounded "expert" that searches, then build an outline and write the article. **Co-STORM** adds a moderator and a shared mind map. This maps well onto the "team brainstorms" feature.
- **Multi-agent debate** (Du et al. 2023, "Improving Factuality and Reasoning through Multiagent Debate"; Liang et al. 2023, MAD with a judge): N agents answer, read the others' answers, and revise for R rounds; a judge aggregates. Diminishing returns after about 2–3 rounds, and the risk is sycophantic convergence, so give agents distinct personas and an explicit "devil's advocate" role.

**Recommended Synapse design**
1. **Bus.** Each project has one `tokio::sync::broadcast::Sender<Event>` for UI and observers (bounded at 1024; on lag, resync from SQLite). Each agent has an `mpsc::Receiver<Envelope>` inbox (bounded). `Envelope { from, to: Agent(id) | Broadcast | Orchestrator, kind: Ask | Answer | Challenge | Refuse{reason} | Delegate{task, budget} | Finding{citations} | Vote | Done, thread_id, reply_to, cost }`. Every message is persisted to SQLite first; it is the event log and replay source.
2. **Roles.** An orchestrator (lead) owns the plan and a budget ledger. Workers (personas) are research subagents with tools. A Critic or Devil's Advocate challenges. A Synthesizer or Writer and a Citation checker finish the work. The user can interject at any time; the user is just another bus participant.
3. **Phases** (a state machine per project run): Brainstorm (STORM-style perspective discovery plus a round-robin of ideas), then Plan (the lead writes research questions), then Research (parallel subagents running a deep-research loop), then Analysis, then Critique/Debate (bounded rounds), then Revised analysis, then Report.
4. **Speaker selection.** In discussion phases, a cheap-model selector (or a rule-based function: pending `Ask` addressed to an agent takes priority, then unanswered challenges, then round-robin) picks the next speaker. Agents can only `Delegate` to agents in their allowed list. `Refuse` is first-class and is logged.
5. **Limits.** `max_turns` per phase, `max_rounds` for debate (2–3), `max_depth` for delegation (2), a parallelism semaphore (`tokio::sync::Semaphore`, for example 3–5 concurrent LLM calls), per-agent and per-project token and USD budgets computed from models.dev `cost`, wall-clock timeouts, and termination detection (all agents `Done`, or the selector says "converged"). `CancellationToken` (tokio-util) on every task, so closing the app or tray stops everything cleanly.
6. **Context management.** Each agent sees a role prompt, the plan, messages addressed to it, and a rolling summary of the shared thread, not the full transcript. Subagents return compressed findings, the key Anthropic lesson.

**Search and read APIs (status today)**
- **Jina Reader `r.jina.ai/<url>`:** works keyless (tested 200) at 20 RPM, or 500 RPM with a free key. It returns clean Markdown and handles JS pages server-side. **Jina Search `s.jina.ai` requires a key** (tested 401 without one).
- **SearXNG** (38k stars, AGPL-3.0): self-hosted metasearch with a `?format=json` API (the JSON format must be enabled in `settings.yml`). It is free and private, but users must run it, for example in Docker. Public instances usually disable JSON or rate-limit it. Offer it as "bring your own SearXNG URL".
- **DuckDuckGo HTML or Lite:** **blocked today** (both endpoints returned an "anomaly" bot challenge to curl). Too brittle to be the default; at most a best-effort fallback.
- **Brave Search API:** the free plan became about $5 per month of credit (around 1,000 queries) in Feb 2026 and requires attribution.
- **Tavily:** 1,000 credits per month free (Nebius is acquiring it).
- **Exa:** the free tier changed in July 2026 to $10 per month of credit.
- **Firecrawl:** has a keyless tier of 1,000 credits per month (per its own blog) and self-hostable AGPL code.
- **Perplexity Sonar:** paid, and returns an answer with citations. It is already in models.dev as the `perplexity` provider, so it can be used as an "LLM with search".
- **Linkup / Parallel:** have monthly free credits.
- **Provider-native web search:** Anthropic `web_search` and `web_fetch` server tools, OpenAI Responses `web_search`, and Gemini grounding. genai 0.6+ maps these as built-in tools. This is the "free with your existing key" path.
- **Recommended free-by-default stack:**
  1. Search, in order of preference: (a) the model provider's native web-search tool when available, (b) the user's SearXNG URL, (c) the user's Brave, Tavily or Exa key, (d) best-effort DDG Lite scrape.
  2. Read: a direct `reqwest` fetch, then **dom_smoothie** (Readability.js port, MIT, 0.18.2) to extract the article, then **htmd** (Apache-2.0, 0.5.5, a turndown.js-style converter) to Markdown. On failure, or for JS-heavy pages, fall back to `r.jina.ai` keyless.
  3. PDFs: the `pdf-extract` or `lopdf` crates, or Jina Reader.
  4. Headless browser: **chromiumoxide** 0.9.1 (MIT/Apache-2.0, last push Feb 2026, a bit quiet) as an opt-in that drives the user's installed Chrome. Do not bundle Chromium, for the RAM goal.
  5. Avoid `html2md` (GPL-3.0+). `fast_html2md` (MIT) is fine as an alternative. The old `readability` crate (0.3.0, 2023) is stale.
  6. Politeness: per-host `governor` rate limiter, robots.txt via the `texting_robots` crate, cache fetched pages in SQLite keyed by URL and ETag.

- **Common format to support:** Markdown with a YAML frontmatter block. Required: `name` and `description`. Optional: `tools` (comma string or list), `model` (`sonnet`, `opus`, `haiku` or `inherit`, so map it to a provider tier), `color`, `emoji`, `vibe`, `permissionMode`. Everything else goes in an `extra` map. Parse with `gray_matter` (crate) or by splitting on `---` and using `serde_yaml_ng` or `serde_norway` (the original `serde_yaml` is deprecated).
- **Import flow:** GitHub API tree listing (`GET /repos/{o}/{r}/git/trees/{branch}?recursive=1`), filter `*.md` excluding README, CONTRIBUTING and so on, then use raw.githubusercontent.com to fetch the files. Unauthenticated requests are limited to 60 per hour, so fetch a tarball (`/tarball/{ref}`) instead of N files. Record repo, sha and license with each imported persona.
- **Agent Skills (SKILL.md):** the format is from `anthropics/skills` (181k stars; the repo has no top-level SPDX license; individual skills carry their own licenses, many Apache-2.0, some source-available) and the open spec at agentskills.io.
  - Layout: a directory `<skill>/SKILL.md` with frontmatter `name` (lowercase-hyphen, at most 64 characters), `description` (at most 1024 characters; says when to use it), optional `license`, `allowed-tools` and `metadata`. Optional `scripts/`, `references/` and `assets/` directories sit alongside.
  - Progressive disclosure: only name and description go in the system prompt; the agent reads the full SKILL.md when relevant.
  - Codex, OpenCode, Gemini CLI, Copilot and Cursor now read the same format. Synapse should support skills alongside personas.

## 8. Storage, memory and RAG

- **rusqlite 0.40.2** (MIT, 124M downloads) with the `bundled` feature compiles SQLite with **FTS5** enabled. It is synchronous; run it on a dedicated thread or `spawn_blocking`, or use `tokio-rusqlite`. Lowest RAM and simplest. Use `rusqlite_migration` for schema migrations.
- **sqlx 0.9.0** (MIT/Apache-2.0): async, with compile-time checked queries, but heavier and loading extensions is clunkier. Not needed for a single-user desktop app.
- **turso 0.8.3** (the Rust rewrite of SQLite, MIT, 24.7k stars) has native vectors and async, but is still pre-1.0 and beta. **libsql 0.10.0** has built-in vector columns, but its future is tied to turso. Revisit in 2027.
- **sqlite-vec 0.1.9** (asg017, MIT/Apache-2.0, last push May 2026). A `vec0` virtual table with brute-force KNN, fine up to about 100k chunks per project. Register it with `sqlite3_auto_extension(sqlite_vec::sqlite3_vec_init)`.
- **Embeddings:**
  - **model2vec-rs 0.3.0** (MinishLab, MIT; crates.io shows "non-standard" license metadata). Static embeddings: `potion-base-8M` is about 30 MB and roughly 100–500× faster than transformers on CPU, with no ONNX runtime. **Lightest viable option.** Download the model on first use from Hugging Face.
  - **fastembed 7.1.1** (Apache-2.0) uses the ONNX runtime (`ort`), which adds about 20–50 MB of binary or dylib and more RAM, in exchange for better quality (bge-small, nomic, rerankers).
  - Alternatively use the provider's embedding API when the user has a key.
- **Lightest memory and RAG design:** SQLite tables `projects`, `agents`, `messages` (the event log), `sources` (url, fetched_at, markdown), `chunks`, a `chunks_fts` FTS5 table and a `chunks_vec` vec0 table. Hybrid retrieval: BM25 from FTS5 plus vector KNN merged with Reciprocal Rank Fusion. FTS5 alone covers most needs; make vectors optional.

## 9. Sandboxing and permissions

- **Claude Code permission model to copy:**
  - Settings `permissions: { allow: [...], ask: [...], deny: [...] }`, with rules like `Read(./src/**)`, `Edit(/docs/**)`, `Bash(npm run test:*)`, `WebFetch(domain:example.com)` and `mcp__server__tool`.
  - Precedence: deny, then ask, then allow; unmatched rules fall to the mode default.
  - Modes: `default`, `acceptEdits`, `plan`, `bypassPermissions`.
  - Scopes: user, project and session (the "always allow for this project" choice).
  - Implementation in Rust: the `globset` crate for path patterns and prefix matching for commands.
  - ACP's `session/request_permission` delivers the same prompts from external CLIs, so one UI serves both.
- **Codex model:** sandbox modes `read-only`, `workspace-write` (writes inside cwd and tmp only, network off by default) and `danger-full-access`, plus approval policies (`untrusted`, `on-request`, `never`). On macOS it uses **Seatbelt** (`sandbox-exec` with a generated SBPL profile); on Linux, **Landlock plus seccomp** (crates `codex-rs/linux-sandbox`, `sandboxing`, `execpolicy` and `windows-sandbox-rs`; Apache-2.0 but not published on crates.io, so vendor or copy). `execpolicy` holds the command-classification rules.
- **Crates:**
  - **nono 0.80.0** (nolabs-ai/nono, Apache-2.0, 4.5k stars, very active): a capability-based sandbox library that uses Landlock on Linux and Seatbelt on macOS. **Best drop-in** for sandboxing shell-tool child processes.
  - **landlock 0.4.7** (Linux only).
  - **Anthropic `sandbox-runtime` (`srt`)** (anthropics/sandbox-runtime, Apache-2.0, 5.5k stars; TypeScript CLI): filesystem and network (proxy) restriction with no container. Usable by shelling out if Node is present.
- **Recommended:** the agent's own file tools (read, write, edit) never touch the OS sandbox. They are in-process functions that check path canonicalization against the project root (`std::fs::canonicalize`, rejecting symlink escapes) and then the permission rules. Writes show a diff preview (`similar` crate) before approval. Shell tools are off by default and, when enabled, run under nono or Seatbelt with workspace-write and no network, plus a timeout and an output cap.

## Resource and footprint notes

- Use one tokio multi-thread runtime with `worker_threads = 2` (I/O bound), alongside GPUI's executor.
- Use rustls rather than OpenSSL to avoid a dylib.
- Do not bundle Chromium or the ONNX runtime by default. model2vec plus SQLite keeps RAG under about 50 MB of RAM.
- External CLI agents are separate processes (Node is about 80–150 MB each). Spawn them lazily, reuse one ACP connection per CLI for many sessions, and kill them on idle.
- Trim the embedded models.dev snapshot at build time (with `canonical_model_id` dedupe it can drop below 200 KB compressed).
